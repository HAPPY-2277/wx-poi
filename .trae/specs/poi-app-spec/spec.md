# POI数据采集及核验移动应用 - 项目规范

## Why

本项目（check@collect）是一款基于微信小程序的POI数据采集与核验移动应用，采用"众包"模式让普通用户参与POI数据的采集与核验，提高数据更新效率，降低运营成本。项目需要一套完整的开发规范以确保团队协作开发的质量和效率。

## What Changes

- 建立完整的MVVM架构模式规范
- 定义标准化目录结构和服务层划分
- 制定统一的API数据交互规范和认证机制
- 明确六大功能模块的实现要求
- 定义组件库设计标准和界面设计规范
- 制定开发流程和质量保障规范

## Impact

- **Affected specs**: 用户认证与权限管理、POI数据采集、POI数据核验、地理信息平台集成、消息通信、文字识别辅助
- **Affected code**: miniprogram/* 全局代码

---

## ADDED Requirements

### Requirement: 项目架构规范

系统 SHALL 采用 MVVM（Model-View-ViewModel）架构模式，符合微信小程序框架特性。

#### Scenario: 架构层次划分
- **WHEN** 开发新页面时
- **THEN** 必须遵循 View（wxml+wxss）→ ViewModel（js）→ Model（services）的层次结构

---

### Requirement: 目录结构规范

系统 SHALL 按照以下目录结构组织代码：

| 目录 | 用途 |
|-----|------|
| config/ | 配置文件（API配置、请求封装、常量定义） |
| services/ | 服务层（认证服务、POI服务、地图服务、消息服务、OCR服务） |
| utils/ | 工具函数（SDK、日期处理、表单验证） |
| pages/ | 页面文件（按模块分类） |
| components/ | 组件库（通用组件、业务组件） |
| images/ | 图片资源 |

#### Scenario: 新增页面
- **WHEN** 需要新增页面时
- **THEN** 在 pages/ 下按模块创建子目录，包含 index.js/wxml/wxss/json 四个文件

---

### Requirement: API数据交互规范

系统 SHALL 遵循统一的JSON返回结构：

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "success": true
}
```

#### Scenario: 请求响应处理
- **WHEN** 前端发起API请求时
- **THEN** 以 `success` 字段作为主要判断依据，`message` 用于显示提示信息，`code` 作为辅助判断

---

### Requirement: 认证与权限规范

系统 SHALL 支持采集者和核验者两种角色权限。

| 角色 | 权限范围 |
|-----|---------|
| collector（采集者） | POI采集、任务接收、消息通信 |
| verifier（核验者） | POI核验、错误标识、消息通信 |

#### Scenario: 权限控制
- **WHEN** 用户访问特定功能时
- **THEN** 系统 SHALL 通过 `wx.getStorageSync('userRole')` 验证用户角色权限

---

### Requirement: 用户认证模块

系统 SHALL 提供以下认证功能：

| 功能 | 描述 | 优先级 |
|-----|------|--------|
| 微信登录 | 通过 wx.login() 获取 code，后端换取 openid | P0 |
| 角色选择 | 用户选择成为采集者或核验者 | P0 |
| 身份绑定 | 微信账号与系统用户绑定 | P0 |
| Token管理 | 存储在 Storage，过期自动处理 | P1 |

#### Scenario: 新用户登录流程
- **WHEN** 用户首次打开小程序时
- **THEN** 检测 Storage 中是否有效 Token → 无 Token 跳转登录页 → 微信登录获取 code → 查询用户是否存在 → 不存在跳转注册页 → 选择角色完成注册

---

### Requirement: POI数据采集模块

系统 SHALL 提供采集者端 POI 采集功能：

| 功能 | 描述 | 优先级 |
|-----|------|--------|
| POI信息采集 | 拍照+表单录入POI信息 | P0 |
| 自动定位 | 拍照时自动获取 GPS 位置（gcj02坐标系） | P0 |
| 照片上传 | 支持多张照片（最多9张）选择与上传 | P0 |
| 分类选择 | POI类别级联选择 | P0 |
| 重新采集任务 | 显示需重新采集的POI列表及原因 | P1 |

#### Scenario: 新建采集任务
- **WHEN** 采集者点击"新建采集"时
- **THEN** 调用 wx.getLocation 获取当前位置 → 用户拍照/选择图片 → 填写POI信息表单 → 提交到后端

---

### Requirement: POI数据核验模块

系统 SHALL 提供核验者端 POI 核验功能：

| 功能 | 描述 | 优先级 |
|-----|------|--------|
| 待核验列表 | 显示待审核的POI数据 | P0 |
| 分类筛选 | 按类别筛选待核验数据 | P1 |
| 核验详情 | 查看POI完整信息（照片、信息） | P0 |
| 错误标识 | 标记错误并填写说明 | P0 |
| 核验通过 | 确认POI信息正确 | P0 |

#### Scenario: 核验操作
- **WHEN** 核验者对POI进行核验时
- **THEN** 可选择"核验通过"、"标记错误"或"无法判定"三种操作，操作结果需记录到数据库

---

### Requirement: 地理信息平台集成模块

系统 SHALL 集成腾讯地图服务：

| 功能 | 描述 | 优先级 |
|-----|------|--------|
| 地图展示 | 显示腾讯地图，支持缩放拖拽 | P0 |
| POI标记 | 在地图上标注POI位置 | P0 |
| 周边搜索 | 搜索POI周边地点 | P1 |
| 导航跳转 | 调用微信/腾讯地图导航 | P1 |

#### Scenario: 地图展示POI
- **WHEN** 地图页面加载时
- **THEN** 调用 wx.getLocation 获取当前位置 → 在地图上展示 POI 标记点 → 用户可点击标记查看详情

---

### Requirement: 消息通信模块

系统 SHALL 提供多类型消息功能：

| 功能 | 描述 | 优先级 |
|-----|------|--------|
| 系统通知 | 接收系统群发通知 | P0 |
| 点对点私聊 | 与指定用户一对一聊天 | P1 |
| 群聊 | 采集者群、核验者群 | P1 |
| 异议提交 | 无法达成共识时提交系统处理 | P2 |

#### Scenario: 消息接收
- **WHEN** 用户收到新消息时
- **THEN** 显示未读标记，消息类型通过 `type` 字段区分（system_notice/quality_notice/private_chat/group_chat/objection）

---

### Requirement: 文字识别辅助模块

系统 SHALL 集成OCR文字识别：

| 功能 | 描述 | 优先级 |
|-----|------|--------|
| 拍照识别 | 拍摄图片识别文字 | P0 |
| 结果展示 | 显示识别出的文字及位置 | P0 |
| 辅助录入 | 一键填充到表单 | P1 |

#### Scenario: OCR识别流程
- **WHEN** 用户上传图片进行OCR识别时
- **THEN** 前端发送图片到后端 → 后端调用腾讯云OCR API → 返回识别结果 → 前端展示并支持选择填充

---

### Requirement: 界面设计规范

系统 SHALL 遵循以下界面设计标准：

| 元素 | 规范 |
|-----|------|
| 状态标签 | 待核验（橙色）、已核验（绿色）、错误标记（红色）、重新采集（蓝色） |
| 颜色主题 | 主色 #07c160（微信绿） |
| 头像尺寸 | 建议 80rpx × 80rpx |
| 昵称截断 | 超过10字符显示省略号 |
| 默认头像 | /images/avatar.png |

#### Scenario: 页面适配
- **WHEN** 页面加载时
- **THEN** 使用 `flex` 布局实现响应式适配，确保在不同屏幕尺寸下正常显示

---

### Requirement: 组件设计规范

系统 SHALL 提供可复用组件库：

| 组件 | 用途 |
|-----|------|
| poi-card | POI信息卡片 |
| category-picker | 级联分类选择器 |
| image-uploader | 图片上传组件 |
| location-picker | 位置选择/展示 |
| status-tag | 状态标签 |
| chat-message | 聊天消息气泡 |

---

### Requirement: 开发流程规范

系统 SHALL 按以下阶段开发：

| 阶段 | 周数 | 目标 |
|-----|------|------|
| 第一阶段 | 1-2周 | 基础框架搭建，完成登录注册 |
| 第二阶段 | 3-4周 | 采集者核心功能开发 |
| 第三阶段 | 5-6周 | 核验者核心功能开发 |
| 第四阶段 | 7-8周 | 地图集成与消息模块 |
| 第五阶段 | 9-10周 | OCR集成与优化 |
| 第六阶段 | 11-12周 | 联调测试与发布 |

**Reason**: 用户反馈注册流程中暂不需要头像上传功能

## 技术约束

1. **包大小限制**: 微信小程序包大小限制 2MB，需注意图片资源优化
2. **网络域名**: 网络请求需在微信公众平台配置合法域名
3. **定位授权**: 地理位置获取需用户明确授权
4. **坐标系**: GPS 位置统一使用 gcj02（火星坐标系）
